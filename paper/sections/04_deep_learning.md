Section 3 showed that classical detectors work on fixed feature vectors that someone has to design. Deep learning offers a different route: neural networks learn a representation of the input themselves, and the anomaly score is computed from that representation. Yadav et al. note that classical methods such as decision trees, SVMs and PCA have been applied to log data, but that they find it hard to capture the hidden relationships between extracted features, which deep models are better placed to learn [Yadav2020]. The deep-learning surveys among our sources focus on logs, that is, on the text records that servers and applications write about their own activity [Landauer2023, He2021, Yadav2020]. Web server access logs are one such source, so this literature carries over directly to web and API traffic.

## 4.1 From raw logs to model input

Logs are semi-structured text produced by logging statements in software [He2021], so they must be turned into numbers before any model can use them. The surveyed work does this in two broad ways [Landauer2023, Yadav2020]:

- **Parsing into templates (log keys).** A log parser separates the fixed part of each message from its variable parameters, so that each message becomes an event type. A sequence of messages then becomes a sequence of event identifiers, which can be counted or fed to a sequence model [He2021, Yadav2020].
- **Working on tokens.** Alternatively, the message text is split into tokens and used directly, without a parser.

The resulting events or tokens are then encoded as vectors. Simple encodings use one-hot vectors or event counts. Others use **embeddings** that capture meaning: LogAnomaly, for example, extracts semantic vectors from the words that make up each event template, so that events with similar meanings get similar vectors [Landauer2023]. Embeddings let a model treat a new but similar message as similar, instead of as an unknown symbol.

## 4.2 Recurrent networks and LSTMs

Recurrent neural networks (RNNs), and in particular Long Short-Term Memory (LSTM) networks, are the most widely used architecture in this literature: Landauer et al. found them in 36 of the 62 approaches they reviewed [Landauer2023]. Their strength is sequences. The best-known example, DeepLog, trains an LSTM on normal log sequences to predict which event comes next. At detection time, if the event that actually occurs is not among the most probable predictions, it is flagged as anomalous. DeepLog also uses a second LSTM to detect anomalies in the parameter values of log messages [Jha2022, Landauer2023]. This is a semi-supervised approach in the sense of Section 2.3: it learns only from normal behaviour. Because it models the order of events, it can catch sequential anomalies that per-request methods like those in Section 3 cannot see (Section 2.2).

## 4.3 Autoencoders and other unsupervised models

An autoencoder is a network trained to compress its input and then reconstruct it. Trained on normal data, it learns to reconstruct normal inputs well, so an input with a high reconstruction error is likely anomalous; a threshold on that error turns the score into a decision [Landauer2023]. Autoencoders and generative adversarial networks (GANs) belong to the small group of deep models that are designed to work without labels at all [Landauer2023]. Even so, fully unsupervised deep approaches remain rare: Landauer et al. count 8 of 62, against 28 semi-supervised ones, because most architectures are easier to train on clean normal data [Landauer2023].

## 4.4 Convolutional networks and transformers

Convolutional neural networks (CNNs), best known from image processing, have also been applied to logs: one approach encodes sequences of event identifiers as a matrix and applies convolutions to it [Landauer2023]. More recent work uses **transformers** and attention mechanisms, which come from natural-language processing. LogBERT, for example, applies a BERT-style transformer to log sequences and is trained semi-supervised [Landauer2023]. These language-based models fit naturally with the token and embedding representations of Section 4.1.

## 4.5 Deep isolation

Deep learning and the classical methods of Section 3 are not exclusive. Deep Isolation Forest maps the data through randomly initialised neural networks to obtain an ensemble of random representations and then applies isolation trees to them [Xu2023]. This keeps Isolation Forest's scalability while allowing non-linear partitions of the original data, and Xu et al. report clear improvements over both isolation-based and deep detectors on tabular, graph and time-series data [Xu2023].

## 4.6 Strengths and limits

Deep models can learn representations and sequential patterns that a hand-designed feature vector would miss, and they reduce the need for manual feature engineering [Yadav2020]. Their main practical constraint is data. Labels for anomalies are scarce, which pushes most work towards semi-supervised and unsupervised training, and Landauer et al. note that these settings are known to detect less well than supervised ones [Landauer2023]. Logs also arrive as a continuous stream, while most reviewed approaches are trained offline [Landauer2023]. Finally, almost all evaluations use a handful of public system-log datasets (HDFS, BGL, Thunderbird and OpenStack) [Landauer2023], none of which is web traffic, so how well these results carry over to web and API traffic is an open question (Section 7).
